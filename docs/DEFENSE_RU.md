# Подготовка к защите

## Что делает программа

Это модель социальной сети. Два источника создают события публикаций и реакций. Подписчики обновляют ленту, уведомления, тренды и статистику. Если публикация содержит spam, обработчик запускает Visitor для соответствующей группы и сохраняет отчёт.

Запуск: `./run.sh 3`. Тесты: `./test.sh`. При первом запуске тестов нужен интернет для загрузки JUnit.

## Observer

Subject хранит подписчиков по типу события. Observer получает событие через onEvent. NetworkEvent — record с неизменяемыми полями; его строки тоже неизменяемы. Выбрана push-модель: данные передаются прямо в событии.

ActivityAggregator реализует Observer и наследует EventSubject. Он принимает исходное событие, увеличивает AtomicInteger и публикует ACTIVITY_SUMMARY. Так получается цепочка наблюдателей.

## Почему нельзя просто вызвать visitor.visit(node)

Если переменная node объявлена как Element, Java выбирает перегрузку по этому статическому типу. Метода visit(Element) у нас нет. Вызов node.accept(visitor) сначала находит реализацию accept конкретного элемента, например Post. Внутри Post this имеет тип Post, поэтому visitor.visit(this) выбирает visit(Post). Затем динамически выбирается реализация метода конкретного Visitor.

## Кто обходит дерево

Обход выполняют посетители. accept только перенаправляет вызов. Например, EngagementVisitor рекурсивно вызывает accept у детей и суммирует результаты. JsonVisitor окружает результаты дочерних узлов JSON-массивом children.

## Что произойдёт при отписке во время публикации

CopyOnWriteArrayList предоставляет итератор по снимку списка. Отписавшийся слушатель может получить уже начатое событие, если он есть в снимке. В новых снимках его уже нет. Обработчик может отписать себя без ConcurrentModificationException. При конкурентных публикациях каждый снимок рассматривается независимо.

## Почему нет потерь при завершении

Каждый finite producer заканчивает публикации, а синхронные обработчики выполняются до возврата publish. ProducerRunner дожидается futures и завершения executor. При сбое одного producer остальные поставленные задачи всё равно завершаются; ошибка возвращается вызывающему коду. Это гарантия внутри процесса при завершающихся обработчиках, а не надёжное хранение после аварии процесса.

## Почему Visitor имеет цену

Новая операция ContentLengthVisitor добавлена отдельным коммитом: изменились только новый посетитель и его тест. Новый элемент Video потребовал метод в интерфейсе Visitor и реализацию во всех посетителях. Если типы элементов меняются часто, такую архитектуру сложнее поддерживать.

## Расчёт вручную

Students: 10 + 3 + 5 + 2 = 20. Clubs: 4 + 6 = 10. Всего 30 реакций в снимке, 2 группы, 6 элементов контента. В отчёте модерации только группа g1 и один подозрительный элемент l1. События реакций отдельно обновляют TrendingListener и не меняют снимок дерева.

## Возможные задания live coding

1. Добавить Visitor, который считает только Photo. Создать класс implements Visitor<Integer>, для Photo вернуть 1, для остальных листьев 0, для контейнеров сумму детей. Добавить тест.
2. Добавить новый тип Audio. Создать record и accept, добавить visit(Audio) в интерфейс и все посетители. Запустить тесты.
3. Добавить слушатель, который отписывается после первого события. Передать Subject в конструктор и вызвать unsubscribe внутри onEvent. Проверить два publish и одно получение.
4. Изменить правило модерации. Вынести новое правило в отдельный Predicate и покрыть обычный и подозрительный текст тестами.
